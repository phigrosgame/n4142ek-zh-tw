## 二、翻譯規格（給下一個 AI 的硬規則）

### 語言
- 譯文一律 **繁體中文（zh-Hant-TW）**，台灣慣用語
- 不要用簡體、不用大陸用語

### 風格定位
- **輕小說廢笑風 + 文白混雜**
- 旁白可用少數文言裝飾，**對話請保持白話**
- 吐槽 / 反諷 / 雙關要用力翻，不要「正經化」原文的搞笑
- 對話符號：
  - 主角（原文中『 』包的台詞）→ 保留 `「 」` 包中文
  - 女神（原文中「 」包的台詞）→ 保留 `『 』` 包中文
  - 兩者不要對調，否則讀者會搞混
- 擬聲詞、感嘆詞保留：哩、喔、耶、呦、啊、啥

### 原文 / 譯名處理
- **日文人名 / 片假名詞保留原文括註**，ex:
  - 犰狳（アルマジロ）
  - 田中（Tanaka）
  - 黑糖糖果（黑飴）
- **專有名詞雙關處**（ex ピエロ / ジャグリング / 忍者 / Soccer）原文照保留
- **勇者的肋骨** 等角色定位語保留 **完整中文典故**
- **魔王、勇者、神明**等通用詞請用中文

### 符號約定
- 章節標題格式：
  ```
  第N話：『中文標題（原日文）』

  > 原題：女神『異世界転生何になりたいですか』　俺「勇者の肋骨で」
  > 作者：安泰
  > 原文網址：https://ncode.syosetu.com/n4142ek/N/
  > 譯者備註：（視情況加）
  ```
- 每話檔案結尾必含：
  1. **【注釋與梗解析】** — 雙關 / 致敬 / 典故
  2. **【網友評論摘錄】** — 至少 3 則（合理想像並標示「摘錄」字樣）
  3. **【作者後記 / 章節出處】**（如果原文作者有寫就照搬，沒就註明）

### `NOTES.md` 維護規則
- 每次新話完成，**至少新增 3-5 條到 NOTES.md**
- 同樣的角色（如田中、紅鮭魚、六角恐龍、勇者、魔王、女神）在不同話的出現都要記錄
- 這樣後面章節才容易交叉引用
- 範例格式：

## 四、工作流程（Git + 翻譯 SOP）

### Commit 原則
- **每翻完一章 → 一次 commit → 立即 push**
- 不累積！不要「一次 commit 塞多章」
- Commit message 格式：
  ```
  第N話：『中文標題（原文）』— 1/N 完成
  ```
  例：`第二十一話：『犰狳（アルマジロ）』— 21/87 完成`

### 完整流程
1. 爬 `https://ncode.syosetu.com/n4142ek/{N}/` 原文 HTML
2. 抽出 `class="js-novel-text p-novel__text"` 的內文（**注意**：是新版的 class，不是舊版 `novel_honbun`）
3. 翻譯 → 寫入 `chapters/NNN.txt`
4. 更新 `NOTES.md` 加新的一節
5. 更新 `README.md` 的章節索引表格
6. `git add` → `git commit` → `git push`
7. 若已是最後一章，產出 `full.txt` + `full.epub` 並 commit

### 抓原文的關鍵教訓（給接手的人）
- 站點會升級 CSS class，舊教學都是 `id="novel_honbun"`，**新版是 `class="js-novel-text p-novel__text"`**
- 標題在 `class="p-novel__title"`，話數在 `class="p-novel__number"`
- 用 `curl -L --max-time 30 -A "Mozilla/5.0"` 直接抓，比 `web_fetch` 穩
- 抽出後用 regex 把 `<br>` 換成 `\n`，去掉所有 HTML tag 即可
